# 识别架构改造：四刀计划

依据：C1/C2 实测（110 包、40 人工核验、30 Unknown 抽样、143 压缩包验证）。
原则：不重写、不加大解析器；每刀单独验证，**tools/ident_regress.sh 必须 PASS 或逐行解释**。

## 目标分层

    PathFacts → AssetType → Evidence(T0-T4) → Decision(Subjects[]/Category) → Presentation

现状把四层揉在一起：路径串直接进首命中规则，结论直接写一个 Subject，再由 RefineBySubject 反向改类别。

## 第 1 刀：证据层独立

- Identify.Scan.Finish 的每个判定点各记一条 Evidence（模型/幸存者目录/HUD/音效/材质/文本/地图）。
- 字段：Asset、RuleId、Hit、Match、Subject、Tier。
- 判定结果不变，只增加可追溯信息。
- 验收：parity PASS；任取 5 个包，证据链能复述"为什么是这个结论"。

## 第 2 刀：规则表显式优先级

- RuleTable 每行加 MatchMode（Exact/Segment/Prefix/Contains）与 Priority。
- Priority 按当前表顺序生成，遍历顺序与今天完全一致（行为等价迁移）。
- 验收：parity PASS；增删一行规则不再依赖"插队"。

## 第 3 刀：类型层独立

- AssetType.cs：PackageKind = ModelBearing / EffectsOnly / SoundOnly / TextureOnly / ScriptOnly / Unknown。
- 只写 ModItem.AssetKind 字段，不改变分类；EffectsOnlyVeto 开关保持默认关。
- 验收：parity PASS；4 个纯特效包的 Kind 判定与 C1.6 一致。

## 第 4 刀：主体数组

- Result/ModItem 的 Subject 改为 Subjects[]（主/辅，各带证据与置信）。
- 字符串投影保留，供树与旧 UI 读取第一个。
- 树、明细、导出三处同步；EffectsOnly 否决作用于主体而非字符串。
- 验收：parity 允许在"多主体包"上出现预期差异，逐条列明；其余包 PASS。

## 不做

- MDL 贴图表 / VMT $model：实测包级收益 0。
- 套装自动合并、跨包关系库：C1.3 已证证据不足。
- ML：无标注集。
