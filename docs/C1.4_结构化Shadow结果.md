# C1.4 结构化 Shadow 结果与归属字段

**性质**：只读 + Shadow 隔离。正式分类、用户分类、分类树、缓存、识别规则均未改。
**仓库**：`_本地版源码`（main，HEAD 75a414b）。**样本**：U 盘 110 个 vpk，全部只读。

---

## 0. 结论

1. **结构化输出已落地**：每个包一份 JSONL 记录，五块分离（资源类型 / 主体 / 影响面 / 归属 / 追溯），另有 TSV 汇总供人看。
2. **主体与影响面的分离是有效的**：4 个特效包主体为空、影响面列出 12 个以内材质名；其余包主体仍来自正式结果投影，未被归属推断改写。
3. **归属字段按证据分级**：A 直接引用 → 组件确认/依赖；B 共享自定义名（且材质是作者自带）→ 可能组件/同源；C 目录/命名 → 仅"有弱关联未证实"。
4. **自动化与 C1.3 人工结论一致 27/40**；9 例更保守（该定组件只给了"未证实"），4 例过度关联（2 例是"依赖"被当成组件语义，2 例是官方材质名导致的误判）。
5. **未做**：套装自动合并、关系图数据库、概率置信度。

## 2. 最小数据结构（实际写入 JSON 的字段）

| 块 | 字段 | 为什么需要 | 类型 |
|---|---|---|---|
| formal | cat/sub/subject/key | 对照用；不改 | 投影 |
| resourceTypes | counts{mdl,vmt,vtf,pcf,wav,bsp} | 类型否决的事实基础 | 事实 |
|  | parse{vmtRead,pcfRead,error} | 区分"没有"与"没读到" | 事实 |
| subject | status{identified_from_formal,effects_only,unknown} / object / evidence[] | 主体只表达"这一包换的是什么" | 推断 |
| impact | objects[] / note | 影响面独立，不得升级为主体 | 推断 |
| ownership | status / relations[{to,type,strength,detail}] | 包与包之间，不写回单包 Subject | 推断 |
| trace | facts[] / inference[] / unresolved[] | 复核用 | 说明 |

**没有加的**：置信分数（未经验证）、每资源关系图（本阶段边界）、套装合并字段（禁止项）。

## 4. Ownership 状态与证据

| 状态 | 定义 | 触发 |
|---|---|---|
| component_confirmed | 已确认组件 | A 直接引用 + 同目录 |
| dependency_confirmed | 依赖已证实（引用别人的资源，但不一定同套） | A 直接引用，不同目录 |
| component_probable | 可能组件 | B 共享自定义名 + 互补（一方有模型）+ 材质为作者自带 |
| shared_source_unproven | 同源未证实 | B 共享自定义名，但双方同类 |
| related_unproven | 有弱关联未证实 | 只有 C/C-（同目录、名前缀） |
| standalone | 无任何候选 | 无关系 |
| insufficient | 信息不足 | 解析失败/无条目 |

证据实现（全部来自文件，无硬编码）：

- **A 直接引用**：包 A 的 PCF 字符串里出现"只由包 B 提供"的材质名（长度 ≥8、全库仅出现 1 次）。
- **B 共享自定义名**：两包含相同 basename，且该名字**只出现在同一目录**、非 `v_/w_` 槽位名；并要求至少一方材质的 `$basetexture` 指向作者自带目录（不是覆盖官方 models/）。
- **C/C-**：同目录 + 文件名最长公共前缀 ≥4 字 / 仅同目录。

## 5. Shadow 输出

- `--shadowjson=文件`：JSONL，一行一个包，UTF-8 无 BOM。
- `--shadowout=文件`：TSV 汇总（带 BOM，Excel 直接看）。
- 运行方式不变：`l4d2_shadow.exe --shadowclass="<目录>" --shadowbase="<基线>" --shadowjson=... --shadowout=...`
- 110 包输出 116 KB（约 1 KB/包）。

样例（雪纺尼克 KSEP）：

```
{"pkg":"...","formal":{"cat":"人物","sub":"二代","subject":"尼克","key":"survivor_gambler"},
 "resourceTypes":{"counts":{"mdl":2,"vmt":40,"vtf":21,"pcf":0,"wav":0,"bsp":0},"parse":{"vmtRead":40,"pcfRead":0,"error":""}},
 "subject":{"status":"identified_from_formal","object":"尼克","evidence":["来自正式结果投影，未重新推断"]},
 "impact":{"objects":[],"note":""},
 "ownership":{"status":"standalone","relations":[]},
 "trace":{"facts":["条目：mdl2 vmt40 vtf21 pcf0 wav0"],"inference":["未触发类型否决","归属判定：standalone"],"unresolved":[""]}}
```

## 8. 风险与未解决

1. **dependency ≠ component**：Scattershot 依赖外部材质包，语义正确但展示上容易被读成"同套"。需要在展示层区分"依赖"与"组件"。
2. **官方材质名仍会漏进来**：同目录 + 非 v_/w_ 判定不足以排除 `spitter` 这类官方名，导致 2 例过度关联。
3. **模型件 + 材质件无法自动连**：霓虹模型主体共享的是"包结构"而不是文件名；要连上需要 MDL 贴图表或 VMT `$model`，本阶段明确不解析。
4. **影响面只对特效包实现**：普通包的 impact 为空。
5. **12 个未知**未强行分类（符合要求）。
6. 依赖关系是"资源级"的，可能跨作者/跨系列，不能直接当套装。
