## 3. Unknown 抽样方法（可复现）

- 总体：C1.6 输出中 `ownership.status == "unknown"` 的 **71** 个包。
- 方法：对包文件名取 **SHA-1**，按十六进制升序排序，取前 **30** 个。
- 该方法是确定性的，任何人用同一份 _shadow16.jsonl 都能复现同一名单，无人工挑选。
- 注意：此处的 Unknown 指**归属关系未知**，不等于主体未知；表中同时记录主体状态。

## 5. Unknown 原因统计

| 判类 | 数量 | 占比 | 含义 |
|---|---:|---:|---|
| A 证据确实不足 | 24 | 80% | Unknown 是**正确结论**：这些 MOD 本来就没有套装关系 |
| B 证据足够但模型未用 | 1 | 3% | 正式结果缺失（无基线）导致投影为空，属流程问题不是规则问题 |
| C 需要额外解析 | 3 | 10% | 材质-only 包要定武器，必须有 MDL 贴图表或 VMT `$model` |
| D 人工也判不了 | 2 | 7% | 只有脚本/说明文件 |

结论：**71 个 Unknown 里绝大多数不是失败**，而是"没有关系"这一事实的正确表达。若把 A 类强行做成关系，等于造假关联。

## 8. 接入风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 误分类 | 类型否决可能误伤"带粒子皮肤的武器包" | 已用"有模型/有音效/有 HUD 即不否决"约束；仍需 30 例复核 |
| Unknown 处理 | 71 个 Unknown 若被当成"待办"会诱发强判 | 明确 Unknown 是终态之一 |
| 用户手动分类优先级 | 否决不能覆盖人工设置 | 只在自动层生效，人工层最后应用 |
| 与正式结果冲突 | 否决会改变 subject | 第一期只写候选标记，不改结果 |
| 缓存一致性 | 规则变化必须触发新缓存 | 复用现有规则指纹机制，逻辑版本号 +1 |
| 旧规则回退 | 需要一键回退 | 开关默认关，回退=关开关 |
| 分类稳定性 | 同一包两次扫描结果必须一致 | 只读 + 确定性判定，无随机 |
| 版本升级兼容 | Shadow JSON 值域已变过一次 | 冻结 JSON 契约，不再改字段语义 |
| 不可逆操作 | 无写操作 | Shadow 与拟接入项都不写用户数据 |

## 9. 最小接入方案（若批准）

1. 只接入一项：**EffectsOnly 类型否决**。
2. 形态：默认关闭的开关；开启后只把候选结果写进日志/诊断，不改 ModItem。
3. 验收：110 包零回归；4 个 EffectsOnly 包人工复核 4/4 同意后，才允许改判定。
4. 回退：关开关即恢复现状。
5. 不做：归属、位置映射、多主体全部留在 Shadow。

---

## 10. 是否值得正式接入

- **值得接入的只有一项**：类型否决。它修的是"粒子包被显示成武器"这种明显错误，且 110 包零回归。
- **不值得接入的**：归属与位置映射。它们目前的价值是解释，不是分类；接入会引入第二个状态源。
- **收益量级**：110 包里影响 2 个（1.8%）。不是大收益，但是可证明的正收益。

---

## 11. 最终决策

**建议：选项 2 —— 仅接入经过验证的少数能力（EffectsOnly 类型否决），默认关闭，其余全部冻结在 Shadow。**

理由与依据：

1. 2/110 真实误判被修正，0 回归，证据可复核。
2. 其余能力没有足够数据支撑接入；强行接入会把"解释"变成"判决"。
3. Unknown 抽样显示 80% 是正确结论，说明当前模型的最大价值是**不乱判**，而不是多判。
4. 后续如要扩展，必须先补 MDL 贴图表/VMT `$model`，否则 C 类缺口无法闭合——那是新项目，不是 C1 的延续。

停止条件（满足其一即停）：类型否决在 30 例复核中出现 1 例误伤；或 110 包出现任何回归。

**本阶段结束，不实施接入。**
