## 2. 资源类型识别结果

### 2.1 判定依据

| 类型 | 依据 | 证据等级 | 限制 |
|---|---|---|---|
| Model（.mdl） | 扩展名 + 目录表 | 事实 | 不解析模型内容（B1 已验证内部名包级增益 0） |
| Material（.vmt） | 扩展名 + 读前 16 KB 取 `$basetexture` | 解析 | 只取一个字段，不解析 shader 树 |
| Texture（.vtf） | 扩展名 | 事实 | 不读图像内容 |
| Particle（.pcf） | 扩展名 + 可打印字符串 | 事实 + 解析 | 只读头尾各 8 KB |
| Sound（.wav） | 扩展名 + 路径段（weapons/player/npc/zombie/horde） | 事实 | 只分「主体音效」与「其它音效」 |
| Map（.bsp） | 扩展名 | 事实 | 不读内容 |
| Script/Config（.nut/.cfg/.txt/.res） | 扩展名 | 事实 | 不执行、不解析 |
| Unknown | 其余 | — | 保留 Unknown，不强行归类 |

### 2.2 粒子材质的认定（关键）

不按名字、不按目录，只用两种**引用证据**：

1. **直接证据**：同一包里某个 PCF 的字符串中出现该 VMT 的文件名（去扩展名、比较最后一段路径）。这是「粒子系统引用了这个材质」。
2. **引用证据**：该 VMT 的 `$basetexture` 指向 `particle/` 下。这是材质自己说的贴图归属，不是材质名。

两者都不看 `materials/particle/` 这个目录，因此 `materials/3ptesturik/` 这种非标准目录也能认出来；反过来，放在 `materials/particle/` 但贴图指向 `models/` 的材质不会被误判。

代码里没有任何「路径包含 particle 就算粒子」的判断——路径只用来统计，不参与类型结论。

### 2.3 判不出来的时候

- 没有 VMT 的包：不判（避免「只有 pcf 就说特效」）。
- 有模型 / 有 HUD 图标 / 有主体音效 / 有 bsp：一律不判为纯特效（附属资源不影响主体）。
- 读不出、超限、坏包：跳过并记录，不影响同批其它包。

## 4. 案例验证

### 4.1 为什么两个 Scattershot 被修正

**4 号**：包里 201 个条目，105 个 pcf、18 个 vmt、18 个 vtf，**没有 models、没有 sound**。18 条 VMT 的 `$basetexture` 全部指向 `particle/3PtestUrik/*`，同时 PCF 里逐个写着 `sniper_scout / sniper_military / sniper_awp / smg_silenced…`。

- 旧逻辑：`Mats` 桶只看目录名，`materials/3ptesturik/` 不在排除名单里 → `sniper_scout` 命中词表 → Subject=鸟狙 → `RefineBySubject` 把大类搬回枪械。
- 新逻辑：PCF 直接引用 18/18 → 粒子材质；无模型/无主体音效/无 HUD → EffectsOnly → 主体留空，18 个材质名进影响面。
- 结果：枪械/鸟狙 → 杂项/特效（影响面 12 项）。

**3 号**：44 个条目，34 个 VMT 全在 `materials/particle/halo`，1 个 pcf 直接引用其中 21 条，无模型。旧结果「一代连喷」来自标题里的「连喷」（`GuessFromText`）。新逻辑判特效，主体未知。

### 4.2 为什么其它含粒子/含模型的没被误伤

| 包 | 内容 | 结果 | 原因 |
|---|---|---|---|
| 1 Scattershot…1.vpk | 37 VMT 全指向 `models/halo/shared/*` | 不变 | 贴图不是 particle，且无 PCF 引用 → 不触发 |
| 2 Scattershot…2.vpk | 2 个 MDL + 7 段武器音效 | 不变 | 有主体证据，直接排除 |
| 特感圣诞帽 | 14 个 MDL | 不变 | 有模型 |
| 火光消除手电HUB2 | 1 个 PCF、0 VMT | 不变 | 没有材质可判，不猜 |
| 米塔屏幕 | 1 个自定义 VMT、0 PCF | 不变 | 无粒子证据，保持未知 |
| 彩色血液 | 4 PCF + 34 VMT | 判定特效，结果不变 | 正式本来就是特效 |

全库 8 个含 PCF 的包：4 个触发特效判定，4 个因有模型/无材质而不触发。

### 4.3 第 3 例说明

`1 [東方Project]⑨琪露诺⑨主题铁喷.vpk` 是 239 条 `materials/particle/water、particle/vistasmoke` 材质，无模型。它和 3 号包里那个 `tiepen.mdl` 同属一个套装的不同分卷。按单个 vpk 看，它是特效材质；按套装看，主体是铁喷。

Shadow 只对单个 vpk 下结论，所以这里给出「特效」。这一例**不算误判，但需要人审**：正式接入前应决定「按 vpk 还是按套装/文件夹归属」。

## 5. 回归风险

| 风险 | 说明 | 处置 |
|---|---|---|
| 套装部件被判为特效 | 第 3 例；套装里本体与特效分卷时，单看分卷会得到特效 | 接入前先做「套装归属」，或对同文件夹内的模型件继承主体 |
| PCF 只读头尾 8 KB | 材质名若只在文件中段，会漏检 → 假阴性（保守，不会误判） | 后续可按需放宽到整文件（单包预算内） |
| VMT 上限 300/包 | 超过 300 条的包只看前 300 条 | 当前最大 239，未触发 |
| 基线含 4 条过期记录 | 早于 v_ 优先规则（2026-11-21），如「木喷/铁喷」两例 | 正式接入时不能拿基线当唯一真值 |
| 3 个包无基线 | BO6 Krig6、子弹堆、爱弥斯入鞘版 | 判为「正式缺失」，不参与一致性统计 |
| 12 个未知主体 | Shadow 不强行分类 | 符合预期，未改动 |

## 6. 最终建议

1. **C1.1 实现成功**：规则通用、可解释、无案例硬编码；类型判定只约束弱名称证据，不产生主体。
2. **C1.2 有实际增益但范围有限**：3 处改判（2 已知 + 1 新发现），0 处新增误判；相对 110 个样本，约 2.7%。
3. **是否进入正式接入**：建议**先不切默认**。先做两件事：① 用「套装/文件夹」决定第 3 例归属；② 建 30–50 条人工核验子集，复跑一次再定。
4. **暂缓**：VMT 内容当对象证据、MDL 贴图名当证据、PCF 深度解析——本阶段数据都不支持。
5. **下一步实验**：按文件夹/套装归属（C1.5 的前置），以及把影响面里的材质名映射到位置表（让「sniper_scout」显示成「鸟狙」）。
