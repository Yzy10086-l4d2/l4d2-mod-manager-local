# C1-Final-Implementation：EffectsOnly 最小正式接入

**范围**：只接入 EffectsOnly 类型否决，默认关闭。未接入归属/位置/多主体；未改分类树、缓存、用户分类。
**验证**：110 包全量、30 例 Unknown 复核名单、开关开/关对比。

---

## 1. 修改文件列表

| 文件 | 改动 | 行数 |
|---|---|---|
| EffectsVeto.cs | **新增**：唯一判定实现 + 只读扫描器 | 299 |
| Core.cs | 配置字段、读取、保存各 1 行 | +3 |
| Catalog.cs | AddVpk 末尾插入否决调用 + ApplyEffectsVeto | +17 |
| ShadowClassify.cs | 判定改为调用 EffectsVeto.Decide；加一致性对账 | +9 |

---

## 2. 代码差异（要点）

- Core：新增 `public bool EffectsOnlyVeto = false`；ini 键 `EffectsOnlyVeto=1`；缺键/读取失败 = false。
- Catalog.AddVpk：`RefineBySubject(it) → ApplyEffectsVeto(it, f) → Add(it)`。
- ApplyEffectsVeto：开关关 → 立即 return（不扫描）；开且有证据 → Cat=杂项、Sub=特效、Subject 清空，再调 `RefineBySubject` 走**原有**整包特效 fallback（得到"特效套装"）。
- Shadow：`IsEffectsOnly` 改为调用 `EffectsVeto.Decide`，不再有第二份规则。

---

## 3. 开关实现

| 项 | 值 |
|---|---|
| 字段 | `Core.Cfg.EffectsOnlyVeto`，默认 `false` |
| ini 键 | `EffectsOnlyVeto=1`（section [platform]） |
| 缺键 | false |
| 读取异常 | false（`Enabled` 里 try/catch） |
| 关闭时 | `ApplyEffectsVeto` 第一行 return，不进任何扫描 |
| 恢复 | 改回 0 即可；不写缓存、不动用户数据 |

---

## 4. 正式分类调用位置

```
AddVpk (Catalog.cs:1193)
  Classify → AnalyzeCached → 字段赋值 → RefineBySubject
  → ApplyEffectsVeto   ← 插入点（1216）
  → Add → CatPrefs.ApplyTo（人工覆盖，1319）
```

- 只对**独立 .vpk** 生效；压缩包内包不扫描（安全跳过）。
- 在 RefineBySubject 之后：可以否决"材质/标题判出来的武器"；在 Add 之前：人工覆盖仍然最后生效。

---

## 5. Shadow 与正式逻辑复用

| 项 | 结果 |
|---|---|
| 判定函数 | 只有一个：`EffectsVeto.Decide` |
| Shadow 调用 | 是（`IsEffectsOnly` 直接委托） |
| 正式调用 | 是（`ShouldVeto → ShouldVetoCore → Decide`） |
| 扫描器 | 各自一份（Shadow 已有计数；正式按需扫描），但**判定规则不分叉** |
| 一致性对账（110 包） | 否决判定 4 条，**与正式实现不一致 0 条** |

---

## 6. 缓存影响

- 未改缓存结构、键、失效策略。
- 缓存只存 `Analyze` 的证据结论（模型/材质/HUD/音效），**不存最终 Cat/Sub**；否决发生在缓存读取之后，因此：开关切换会在下次扫描立即生效，不需要清缓存。
- 不需要缓存变更，故未提交缓存方案。

## 11. 意外变化

1. **⑨琪露诺 1 号被改判**：它只有粒子材质，C1.6 判 effects_only；但 C1.3 认为它与 3 号（模型件）可能是套装。开启开关后它的正式结果显示为"特效"，而不是"铁喷"。
   - 这是"单包证据正确、套装归属未定"的已知矛盾，不是新 bug。
   - 处置建议：合并前先人工定性；若定性为套装部件，应保持开关关闭或另立套装层任务，不要在本期加特例。
2. 无其它变化；107 包完全一致。

- 数据回退：无写操作，无需清理。

## 13. 是否建议合并

**建议：可以合并，但保持默认关闭，并在开启前完成两项前置条件。**

前置条件：

1. 人工定性 ⑨琪露诺 1 号（是否套装部件）。若定性为部件，则本期不开启开关，或把启用范围限定为"无任何跨包关系的包"（需另立任务，不在本期实施）。
2. 开启后观察一轮：只记录否决日志、不改显示，再决定是否真正生效。

依据：110 包零回归、Shadow/正式判定 110/110 一致、手动分类优先级不变、无缓存与数据风险；唯一的不确定点是 ⑨ 这一类"套装部件被单独判特效"，属于已知边界，不是本实现引入的错误。
