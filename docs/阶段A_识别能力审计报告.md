## 0. 结论

1. **现有系统不是知识驱动，是路径模式匹配加逐对象补丁。** 判定输入只有一样东西：VPK 目录表里的路径字符串（`Vpk.WalkBuffer / Walk`，Mods.cs:762 / 857，逐条 `onPath(full.ToLowerInvariant())`）。全流程没有解析过任何一个 .mdl、.vmt、.vtf、.pcf、.nut 的内容。
2. **唯一被读进来的「内容」是 addoninfo.txt 的标题、作者和描述**（`Vpk.ReadAddonInfo`，Mods.cs:930）。它只用于最后兜底，不参与任何实体判定 —— 这个取舍是对的（作者标题常与内容不符），但也意味着系统对「文件里面是什么」一无所知。
3. **知识以「特征串 → 名字」的扁平表存在**：`Dict` 110 条、79 个目标名；`AliasKeys` 43 条；`InfectKeys` 9 条；`SurvivorDirs` 8 条；`Positions` 83 个位置。表里只有「字符串 → 显示名」，没有对象、属性、类型、关系。**没有「这个材质属于哪把枪」这种知识，只有「路径里有 ak47 就叫 AK-47」这种联想。**
4. **资源之间的关联全靠目录约定，共 4 条**：`models/survivors/<人名>/`、`materials/models/survivors/<人名>/`、`materials/vgui/hud/icon_<对象>.vtf`、`sound/weapons/<对象>/`。约定之外的布局一律退化到「文件名里有没有那个词」。
5. **判定是「第一个命中即返回」，没有证据聚合。** `Feature()` / `Lookup()` 是线性扫表取第一个子串命中（Identify.cs:212 / 232）；`ClassifyByPaths` 是 15 个 `return true` 顺序早退（Identify.cs:1027-1190）。因此「表序」事实上就是优先级，重复资源（几十个材质都含 shotgun）不会被识别为「同一条证据的重复」，只会被当成一次命中。
6. **不确定与确定同形**：结果只有 `Subject` 字符串和 `Level` 字符串，没有置信度、没有状态、没有冲突记录。认不出的包统一落到「未归类」，与「看过了但没有有效证据」不可区分。
7. **覆盖率的真实数字**：`Positions` 83 个位置里，78 个能由 `Dict` 触达，5 个（弹道、通用、地面细节、场景贴图、平台）只能由内容分类或特殊分支触达；`Dict` 里有 1 个目标名（石头）在位置表里不存在，识别得出、树上无位可落。
8. **可复用的地基比想象中多**：位置表已经是真正的对象清单（带中英名和别名），`Level + Trace` 是证据分级的雏形，包指纹 `Fp` 是跨路径的稳定身份，VPK 目录树解析（含 zip/rar/7z 内嵌包）已经跑通，自检与基线 diff 是可用的验证设施。**缺的不是数据量，是「对象—资源—证据」这三层结构。**

一句话：**现在的识别是「看路径联想名字」，任务书要的是「看资源推断对象」。两者差的不是规则数量，是一次表示层的更换。**

## 2. 当前识别系统架构

### 2.1 分层

```
┌─ 输入层 ────────────────────────────────────────────────┐
│ Vpk.Walk / WalkBuffer        只回路径字符串（Mods.cs:762/857）│
│ Vpk.ReadAddonInfo            读 addoninfo.txt 标题/作者     │
│ Catalog.ListArchive           zip / rar / 7z 内嵌 vpk 列表  │
│ Identify.TreeOfArchive       从压缩包里只取 vpk 目录表前缀   │
└──────────────────────────────────────────────────────────┘
                        ↓ 路径列表
┌─ 分拣层 Scan.Feed（Identify.cs:270）────────────────────┐
│ .mdl → Mdls；hud/icon_*.vtf → Huds；sound/weapons/* → Snds │
│ materials/* → Mats（剔除 particle/decals/vgui/effects…）     │
│ maps/*.bsp、scripts/*、particles/* → 布尔                │
│ 同时累积 Assets（模型+材质完整路径，上限 4000 条）            │
└──────────────────────────────────────────────────────────┘
                        ↓
┌─ 判定层 Scan.Finish（Identify.cs:360）──────────────────┐
│ 1 地图(bsp) → 2 模型名(v_ 优先) → 3 幸存者按人目录          │
│ 4 主件=命中次数最多，其余拼成 Kinds 的「附带:」              │
│ 5 HUD 图标名 → 6 音效目录 → 7 材质（先按人目录，再通用）      │
│ 8 特感覆盖≥2 种 → Subject=通用                             │
└──────────────────────────────────────────────────────────┘
                        ↓ Result{Subject, Level, Key, Kinds, Trace, Assets…}
┌─ 补丁层 ────────────────────────────────────────────────┐
│ FillAddonInfo → GuessFromText（仅 Subject 为空时）          │
│ UpgradeShotgunByText（霰弹枪格，文件名可覆盖材质结论）        │
│ Catalog.RefineBySubject（Sub 与 Subject 对齐、AnimOnly→平台）│
└──────────────────────────────────────────────────────────┘
                        ↓
┌─ 分类层 Catalog.Classify（Catalog.cs:1320）─────────────┐
│ 目录规则（三方地图/人物/喷漆/医疗/特感/物品储藏库）            │
│ 否则 ClassifyByPaths（Identify.cs:1027，15 个早退出口）     │
└──────────────────────────────────────────────────────────┘
                        ↓ Cat / Sub
┌─ 落位层 SlotIndex.Build（CatTree.cs:43）────────────────┐
│ 名字洗一遍（SplitKind / Vague / Concrete / Disambiguate）  │
│ 同一位置聚成槽；认不出的整组不收 → 未归类                    │
└──────────────────────────────────────────────────────────┘
```

### 2.2 三处「同一件事、两套判定」

| 判定对象 | 路径一 | 路径二 | 谁赢 |
|---|---|---|---|
| 大类小类 | `Catalog.Classify` 的目录规则 | `ClassifyByPaths` 的内容规则 | 目录优先，内容兜底 |
| 对象名 | `Scan.Finish` 的四级证据 | `ClassifyByPaths` 里「单枪 HUD 图标」「药品」等段落也会产出对象 | `RefineBySubject` 事后对齐，条件复杂 |
| 落位名 | `Subject`（识别结果） | `SlotIndex` 的 Name（洗过） | 树里显示洗过的，明细里显示原值 |

这不是设计缺陷本身，而是**没有中间表示**的必然结果：没有「对象」这个层，所有结论都只能直接写成字符串，谁先写谁算。

## 3. 从资源到最终分类的流程

```
一个 vpk
  │
  ├─ 能读出目录表吗？ ── 否（坏包 / 分卷缺失 / 7z 里取不到）→ 空结果（与「没资源」同形）
  │
  ├─ 有 maps/*.bsp ? ── 是 → Level=地图，Subject 清空，大类=地图 ──→ 落位：不进树（地图不占位置）
  │
  ├─ 有 models/**/*.mdl ? ── 是 → 查 Dict（v_ 优先）
  │        ├─ 命中 1 个 → Subject=该对象，Level=模型
  │        ├─ 命中多个 → 取命中次数最多者为主件，其余写进 Kinds「附带:」
  │        └─ 一个都没命中 → 看 models/survivors/<人名>/ → 1 人=该角色，≥2 人=幸存者
  │                              └─ 仍无 → 看是否全 anim_/gestures_ → AnimOnly=真
  │
  ├─ 无 mdl，有 hud/icon_<对象>.vtf ? ── 是 → Subject=该对象，Level=HUD图标
  │
  ├─ 无上述，有 sound/weapons/<对象>/ ? ── 是 → Subject=该对象，Level=音效
  │
  ├─ 无上述，有 materials/* ? ── 是 → 先按 materials/models/survivors/<人名>/ 判人
  │                                     再逐条 Lookup 材质路径 → Level=材质
  │
  └─ 仍然空 → 读 addoninfo 标题/描述 → AliasKeys 词表兜底（Level=标题）
             └─ 还空 → 落「未归类」

分类（与上一步并行、互不感知）
  ├─ 所在目录命中「三方地图/人物/喷漆/医疗物品/特感/物品储藏库」→ 直接定大类小类
  └─ 否则 ClassifyByPaths：地图 → 战役素材卷 → 天空盒/地面细节 → 人物(按人数)
        → 小僵尸 → 特感通用 → 特感 → 药品 → 枪械/近战/投掷物/弹药升级
        → （无 mdl 时）喷漆 → 单枪 HUD 图标 → 整套 UI → 弹道 → 特效 → 音效 → 脚本
```

流程上有个结构性事实：**「对象」和「类别」是两条独立的路，各自走到终点，最后靠 `RefineBySubject` 在有限条件下对齐。** 任何一条路判错，另一条不会纠正它，只会产生「分类对、位置空」或「位置对、分类错」的组合。

## 7. 问题与根因

### 根因 R1：输入退化成「路径字符串」，丢掉了可用信号

`Vpk.Walk` 逐条回调路径后，18 字节元数据（CRC、预载长度、归档号、偏移、长度）**直接跳过**（Mods.cs:777 / 890）。文件大小、是否在分卷、数据段位置全部丢弃。这些恰恰是判断「资源是否完整」「是不是同一套」的低成本信号。

**后果**：只能靠名字猜；同名不同内容、内容相同不同名，都只能靠 `Fp` 事后补考。

### 根因 R2：知识停留在「字符串 → 名字」，没有对象与关系

`Dict` 一行就是一条知识：`{"shotgun_chrome", "铁喷"}`。它不知道「铁喷」是霰弹枪、官方模型是 v_shotgun_chrome / w_shotgun、材质目录在 materials/models/v_models/weapons/。

**后果**：无法回答「这个材质属于哪把枪」「这个动画是给谁的」；每遇到新问题只能加一行字符串。

### 根因 R3：判定是早退，不是证据聚合

`Lookup` 返回第一个命中（Identify.cs:232）；`ClassifyByPaths` 15 个出口按顺序早退。没有「收集—加权—裁决」的过程。

**后果**：一条弱证据（材质路径里有 shotgun）和一条强证据（v_shotgun_spas.mdl）在流程里地位相同，谁先被扫到谁算；重复资源（几十张贴图都含同一词）不会被识别为「同一条证据」，反而放大确定性。

### 根因 R4：优先级隐含在表序与代码顺序里

`"shotgun" → 铁喷` 正确的唯一原因是 4 条更具体的 shotgun_* 排在它前面。任何人插一行就可能翻案，而且没有测试会报警。

**后果**：规则不可推理、不可排序、不可统计；新增规则的副作用无法预估。

### 根因 R5：没有状态与置信，「不确定」被压成「未归类」

Result 只有 `Ok` 布尔（Entries > 0）。坏包、7z 读不出、真没有可识别资源，三者同形。

**后果**：用户看到「未归类」不知道是「系统没看懂」还是「这包确实没有可识别内容」；没法做「待复核」队列。

### 根因 R6：缓存身份与人工身份不一致

识别缓存键是 `RelPath`（Identify.cs:1330），人工归类键是包内容指纹 `Fp`（Catalog.cs:1283）。改名后人工记得住、缓存记不住。

**后果**：缓存命中率虚低，改动后的回归对比噪声大。

### 根因 R7：缓存失效把「逻辑」当「数据」

`RuleFingerprint()` 只哈希 4 张表 + 位置表，逻辑版本是一行手写串 `rules:2026-11-22a`（Identify.cs:877）。

**后果**：改判定逻辑忘了改这行 → 全库沿用旧结论，且没有任何提示。这是「改了没效果」类问题的头号来源。

## 8. 能力边界：什么样的 MOD 现在必然认不出

按「输入可用的信息」分五类，每一类都给一个具体形态：

1. **资源在非标准目录**。模型放在 `models/custom/<作者>/<任意名>.mdl`，文件名里没有官方对象名 → `Dict` 全不命中，`SurvivorDirs` 也不命中 → 未归类。这是最常见的一类。
2. **只有材质、没有模型**。一张 `materials/models/weapons/custom/ak_skin.vtf` → 命中 "ak" 判 AK-47（运气好），换成 `skin_01.vtf` 就完全无解，**因为不读 VMT，不知道它挂在哪把枪上**。
3. **替换类但对象名不在词表**。新武器 / 新近战 / 自定义道具（P90、M4A1 这类游戏里根本没有的）→ 有意不进树（CatTree 里 `!StandardName` 直接 `continue`），只剩未归类。
4. **混合包且主件不明确**。一个包里两把枪的模型数量相同 → 取第一个命中的当主件，另一把只进 `Kinds` 字符串，树上永远只显示一个。
5. **纯动画 / 纯脚本 / 纯粒子**。动画靠 `anim_` 前缀，脚本与粒子只有布尔标记，能落到「杂项/其他」，但说不出改的是什么。

反过来，**能稳定的**是：官方命名规范内的模型包、带 bsp 的地图、整包 HUD、喷漆、weapons 目录下的音效。这也解释了为什么「收录库 + 专属规则」看起来有效——它是在用样本量弥补表示层的缺失。

## 9. 整改建议与优先级

排序原则：**先补输入与表示，再改判定，最后加策略。** 顺序颠倒会白做。

| 优先级 | 建议 | 对应根因 | 预期收益 | 风险 | 验证 |
|---|---|---|---|---|---|
| P0 | 识别结果改结构化（对象 / 类别 / 证据列表 / 状态 / 冲突） | R3 R5 | 让后续所有改动有落点；先做投影，行为零变化 | 低 | idcheck 零改判 + 往返序列化相等 |
| P0 | 规则表加显式优先级与匹配方式（精确/段/前缀/包含），表序不再承担语义 | R4 | 新增规则可预估副作用 | 中（15 个出口要保序迁移） | 改任一规则 → 指纹变；不改 → 指纹不变 |
| P1 | **补 VMT 解析**（$basetexture → 贴图名；$model 上下文），建立「材质 → 贴图 → 候选对象」链 | R1 R2 | 第 2 类边界（纯材质包）从「靠运气」变「可推断」；成本最低、收益最高 | 低（只读文本纹理文件） | 用 20 个纯材质包做前后对比 |
| P1 | 补 MDL 头部解析（材质名列表 / 骨骼名），建立「模型 → 材质」链 | R1 R2 | 模型在非标准目录时也能反查对象；识别「附件 / 换骨」类 | 中（二进制格式，需容错） | 与现有模型名判定做交叉验证，冲突样本必须进冲突记录 |
| P1 | 资源关联从「4 条目录约定」升级为「关系表 + 目录约定兜底」 | R2 | 武器↔配件、角色↔材质、地图↔资源不再依赖路径写法 | 中 | 构造 10 组非标准目录样本 |
| P2 | 证据聚合替换早退（收集 → 去重 → 按证据级裁决 → 冲突保留） | R3 | 多主体、混合包、冲突证据可表达 | 高（会改变现有判定结果，必须逐条核） | 基线拆「已核验/仅观测」后分组对比 |
| P2 | 缓存键改 Fp 优先、RelPath 兜底；逻辑版本独立成常量并自检 | R6 R7 | 「改了没效果」类问题归零 | 低 | 改名/移动/复制三场景 |
| P2 | 状态机：已识别 / 未知 / 待复核 / 混合，进入未归类页分组 | R5 | 用户能看出「谁没看懂」 | 低 | 未归类页按状态分组的 UI 用例 |

**明确不建议现在做的**（对应任务书禁止项）：

- 不做 MOD 收录库、不做「按文件名查表」的扩充——那是把 R2 的错误放大。
- 不引入机器学习：现有标注只有 152 行且未核验，特征还是路径字符串，没有可学的表示。
- 不先动 `SlotIndex` 的名字修正逻辑（`SplitKind/Vague/Concrete`）：它现在是「呈现层的创可贴」，等 §P0 的模型落地后再决定是删是留。
