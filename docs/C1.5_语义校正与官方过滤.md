# C1.5 关系语义校正、官方资源过滤与多主体验证

**性质**：只读 + Shadow。正式分类、用户分类、分类树、缓存、识别规则均未改；未合并套装。
**样本**：U 盘 110 个 vpk；官方名基准取自游戏 `left4dead2\pak01_dir.vpk`（17 646 条 / 17 118 个名字）。

---

## 0. 结论

1. 归属状态改为五种互不升级的语义：`component / possible-component / same-origin / dependency / unknown`，依赖与同源都不会自动变成组件。
2. 官方资源过滤改为**读游戏自带 pak01_dir 的名字表**，不是关键词表；本次过滤 183 个名字参与关联。
3. 过滤后，Scattershot 4 号原先的"依赖"消失——那 5 个材质名其实是官方粒子资源，C1.4 判成依赖是错的；3 号还剩 1 条非官方依赖。两例都没有变成组件，符合预期。
4. 彩色血液、特感高亮：前者已归零；后者仍被误判为 possible-component（pak01 里查不到 `spitter.vmt` 这类材质名，属于官方名识别缺口）。
5. 多主体已能表达：2 个包输出多个主体（特感圣诞帽 10 个、大肥鱼石头 8 个），每个主体带独立证据与状态。
6. 与 40 个人工结论：一致 29、过度关联 2、保守 9。

## 1. 关系语义

| 类型 | 含义 | 证据门槛 | 可否推出组件 |
|---|---|---|---|
| component | 同一套 MOD 的不同组件 | A 直接引用 **且** 同目录 | 是 |
| possible-component | 可能同套，证据不足 | B 共享自定义名 + 资源互补 + 材质为作者自带 | 否（仅标记） |
| same-origin | 同基座/同来源，不是同套 | B 共享自定义名但双方同类 | 否 |
| dependency | A 使用/引用 B 的资源 | A 直接引用，跨目录 | 否 |
| unknown | 无足够证据 | 只有目录/命名，或无关系 | 否 |

禁止的转换：dependency→component、same-origin→component、任何关系→合并。

## 2. Scattershot 3/4 验证

| 包 | 引用是否真实 | 引用对象 | C1.4 结论 | C1.5 结论 | 判定 |
|---|---|---|---|---|---|
| 3 | 是 | 1 个非官方材质（另 5 个是官方粒子名） | 依赖 | **dependency** | 正确 |
| 4 | 是 | 5 个全是官方粒子材质名 | 依赖 | **unknown** | **修正**：引用官方资源不构成依赖 |

两例都没有被判为 component，也没有互相合并。正式分类未动。

## 3. 官方资源过滤

- **来源**：游戏 `pak01_dir.vpk` 目录表 → 17 118 个 basename（带扩展名与去扩展名两种形式）。
- **用途**：只限制"归属推断"里的名字使用；资源事实、影响面、Trace 中照常保留。
- **过滤点**：A（PCF 引用的材质名）、B（两包共享名）。
- **本次结果**：183 个名字被过滤；依赖关系从 C1.4 的 5 条降到 3 条。

缺口：pak01 里查不到 `spitter.vmt` 这类材质名（游戏只带 `spitter_normal.vtf`），所以"官方材质名"仍有漏网。当前靠"作者自带贴图"辅助判断，特感高亮仍被误判为 possible-component。

## 4. 多主体

结构：`subject.objects[]`，每项含 object / status / evidence；`multi` 布尔。

| 包 | 主体 | 状态 |
|---|---|---|
| 特感圣诞帽 | 通用 + witch/spitter/smoker/jockey/hunter/hulk/charger/boomette/boomer | 1 个来自正式结果，9 个 candidate_from_model |
| 大肥鱼 token 石头 | 石头 + 7 个 concrete_spawnchunk 变体 | 同上 |

规则：候选只从"包内官方模型名"推，不猜中文对象名；不足 3 个不同官方模型就不生成多主体。**不把影响面伪装成主体**。

## 9. 失败与未解决

1. **官方名识别有缺口**：pak01 缺少部分官方材质名（如 spitter.vmt），导致 2 例过度关联仍存在。
2. **模型件与材质件仍连不上**：霓虹模型主体 vs α 材质，需要 MDL 贴图表或 VMT `$model`，本阶段禁止。
3. **67 个 unknown 偏高**：过滤从严，弱证据不再升级；是否符合预期需人工抽样确认。
4. **多主体候选是英文模型名**：没有映射成中文对象名，展示层需要再接一步。
5. **多主体判定阈值（≥3 个官方模型）是拍的**：本语料只验证了 2 例，未验证边界。

---

## 10. 建议

- C1.5 目标达成：语义分离、官方过滤、多主体表达三项都落地并有回归数据。
- **下一步（C1.6）建议只做**：① 官方名缺口补齐（用路径域 + pak01 双判据）；② 把依赖/同源/组件的展示分层；③ 多主体候选映射到位置表。
- **仍不做**：套装合并、关系图数据库、MDL/VMT 深层解析。
- 进入正式接入前，必须先用 30–50 条人工核验确认 67 个 unknown 是否过保守。
